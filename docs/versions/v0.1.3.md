## Fixed

- **TIFF metadata extraction**: Magick.NET's TIFF encoder silently drops `ExifProfile` (TIFF embeds EXIF as native IFD tags, not as an APP1 segment). The TIFF-specific tests and `GenerateSamples` now use XMP — which survives the TIFF write/read round-trip — so metadata injection, extraction, and stripping are all exercised correctly. Real-world TIFFs from cameras (which carry an ExifIFD sub-directory) are handled correctly by the existing `GetExifProfile()` path and are unaffected.
- **`ExtractImageMetadata` defensive fallback**: Added an attribute-based fallback that collects any `EXIF:*`-prefixed image attributes when `GetExifProfile()` returns null, covering formats that expose EXIF via attributes rather than a structured profile.
- **`CreateXlsx` / `CreatePptx` test helpers**: `Package.Open` buffers ZIP data until the package is disposed. `ms.ToArray()` was called before `Dispose()`, returning an empty byte array. Fixed by scoping the package in an explicit `using` block so the ZIP is flushed before the byte array is captured. Affected 4 tests (XLSX/PPTX creator extraction, ODC and O11).
- **`BuildMinimalAvi` test helper**: The previous stub was 12 bytes (RIFF header only), which TagLib cannot parse. Replaced with a structurally valid 224-byte AVI containing the required `LIST hdrl` (with `avih` and `LIST strl > strh + strf`) and `LIST movi` chunks. Affected 3 AVI metadata tests (ODC and O11).
- **`GenerateSamples` TIFF output**: `SetProfile(exif)` on a TIFF image is silently ignored by Magick.NET's TIFF encoder; the generated sample contained no metadata. Replaced with an XMP profile and a `Comment` field, which both survive the write/read cycle.
